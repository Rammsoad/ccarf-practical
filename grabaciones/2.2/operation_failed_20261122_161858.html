╭────────────────────────────────────────── 💡 Concepto del examen ──────────────────────────────────────────╮
│                                                                                                            │
│  Un error genérico ('Operation failed') no le dice a Claude si conviene reintentar, pedir otro dato o      │
│  escalar. Peor aún: devolver lista vacía cuando el sistema falló hace que Claude diga algo FALSO ('no      │
│  tienes pedidos').                                                                                         │
│  Error estructurado = is_error: true + errorCategory (transient / validation / business / permission) +    │
│  isRetryable + description legible. Y un resultado vacío válido NO es un error.                            │
│  En MCP el campo se llama isError en el resultado de la tool; en la Messages API es is_error en el bloque  │
│  tool_result. Misma idea.                                                                                  │
│                                                                                                            │

📊 Demo 2.2 · Qué recibió Claude en cada escenario
Rojo: Claude no puede saber qué pasó. Amarillo: vacío válido, pero se ve igual que una falla. Verde: el error (o el vacío) viene explicado.
Tu código o una toolBloqueado / falló / faltóDatos de entrada
👉 Con el formato genérico, en 'caido' Claude recibe una lista vacía sin error: no tiene cómo saber que el sistema falló y le dice al cliente algo falso. Con errores estructurados, cada respuesta trae la categoría y si conviene reintentar.

╭────────────────────────────────────────────── 🧪 Experimenta ──────────────────────────────────────────────╮
│                                                                                                            │
│  Compara 'caido · generico' con 'caido · estructurado': con la lista vacía Claude no tiene forma de saber  │
│  que hubo una falla.                                                                                       │
│  Sube D22_FALLAS_TRANSITORIAS a 3 y mira cuántas veces reintenta.                                          │
│  En un sistema multiagente, el subagente reintenta lo transitorio localmente y solo propaga al             │
│  coordinator lo que no pudo resolver, con lo que intentó y resultados parciales.                           │
