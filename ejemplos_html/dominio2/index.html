Demo 2.1 · Descripciones de tools y selección

¿De qué va esta demo? (clic para ocultar)

📖 De qué trata esta demo

Claude elige una tool leyendo solo tres cosas: su name, su description y su input_schema. No ve tu código ni sabe qué hace la función por dentro. Si dos descripciones se parecen, la selección se vuelve una moneda al aire. Mejorar las descripciones es el primer arreglo, antes que ejemplos few-shot o un clasificador.

🧪 Qué esperar

  • Los nombres ya dicen mucho, así que con las mínimas Claude acertará varias. Las diferencias salen en los casos frontera:
  • "¿Cuánto me cobraron de envío en el pedido #12347?" → con mínimas suele irse a get_shipping_rates por la palabra "envío". Lo correcto es lookup_order, porque es un pedido ya hecho.
  • "Mi pedido no llega, mi correo es…" → con mínimas suele irse a lookup_order por la palabra "pedido". Lo correcto es get_customer, porque no hay número de pedido y con el correo se obtiene la lista.
  • Mira también el input: con query Claude manda la frase completa; con email, order_id o codigo_postal manda justo el dato.
  • Los resultados pueden variar entre corridas. Eso mismo es parte de la lección.

🎓 Lo que pregunta el examen

  • Descripción mínima o traslapada → selección poco confiable. Arreglo: descripciones con formato de entrada, ejemplos, casos frontera y límites.
  • Renombrar tools para quitar traslapes, o dividir una tool genérica en varias con propósito claro.
  • Revisar el system prompt cuando una tool se elige "sin razón".

Cómo leer cada tarjeta: arriba, las variables de esa corrida (en amarillo lo que cambió respecto a la anterior). Luego el diagrama, con su leyenda de colores. Al final, en verde, 👉 la conclusión: lo que tienes que llevarte.

Demo 2.2 · Errores estructurados vs genéricos

¿De qué va esta demo? (clic para ocultar)

📖 De qué trata esta demo

Qué le regresa tu tool a Claude cuando algo sale mal. Hay dos errores clásicos:

  1. Error genérico ("Operation failed"): Claude no sabe si reintentar, pedir otro dato o escalar.
  2. Error silenciado: el sistema falló, pero la tool devuelve una lista vacía. Claude cree que la consulta funcionó y le dice al cliente algo falso ("no tienes pedidos").

La solución es un error estructurado: is_error: true y en el contenido errorCategory (transient, validation, business o permission), isRetryable y una description legible. Y un resultado vacío que sí es válido no es un error.

🧪 Qué esperar

  • caido · generico es el momento clave: Claude dice que no hay pedidos, cuando en realidad el sistema estaba caído. En estructurado reintenta y en el 2.º intento obtiene los pedidos.
  • Con el genérico, Claude a veces adivina bien (por ejemplo, nota que ana@ejemplo está mal escrito), pero lo hace por su cuenta: la tool no le dio esa información.
  • La tabla final pone lado a lado las llamadas, la respuesta y lo que debería pasar.

🎓 Lo que pregunta el examen

  • Metadata de error estructurada para que el agente decida: reintentar, explicar o escalar.
  • Distinguir una falla de acceso de un resultado vacío válido.
  • En multiagente: el subagente reintenta lo transitorio localmente y propaga al coordinator solo lo que no pudo resolver, con lo que intentó y resultados parciales. No suprimir errores ni detener todo por una sola falla.

Cómo leer cada tarjeta: arriba, las variables de esa corrida (en amarillo lo que cambió respecto a la anterior). Luego el diagrama, con su leyenda de colores. Al final, en verde, 👉 la conclusión: lo que tienes que llevarte.

Demo 2.4 · Servidor MCP propio + Agent SDK

¿De qué va esta demo? (clic para ocultar)

📖 De qué trata esta demo

MCP (Model Context Protocol): un estándar para que un agente descubra y use tools y datos de sistemas externos. Un servidor MCP ofrece:

  • Tools: acciones que Claude puede llamar.
  • Resources: datos que se pueden leer, como un catálogo o documentación.

La demo crea un servidor propio, primero le habla sin Claude y luego se lo conecta a un agente.

🧪 Qué cambia entre una corrida y otra

  • D24_USAR_RESOURCES = True: el agente también recibe ListMcpResourcesTool y ReadMcpResourceTool, y puede leer el catálogo completo en vez de buscar a ciegas.
  • Empeora la descripción de buscar_producto (por ejemplo, "Busca.") y compara.
  • Abre servidor_inventario_mcp.py y agrega una tool nueva. El lab no sobrescribe tu versión si el archivo ya existe; bórralo para volver al original.
  • D24_SECRETO = "en_archivo": el token queda escrito en el .mcp.json que va a git.
  • D24_ALCANCE = "usuario": el servidor queda en ~/.claude.json y tu compañero no lo tiene.

🎓 Lo que pregunta el examen

  • .mcp.json del proyecto contra ~/.claude.json del usuario, y expansión de variables ${VAR} para secretos.
  • Las tools de todos los servidores configurados se descubren al conectar y quedan disponibles a la vez.
  • Mejorar la descripción de las tools MCP para que el agente no las ignore y use built-ins como Grep en su lugar.
  • Resources como catálogo de contenido para ahorrar llamadas exploratorias.
  • Servidores de la comunidad para integraciones estándar; uno propio solo para flujos específicos del equipo.

Cómo leer cada tarjeta: arriba, las variables de esa corrida (en amarillo lo que cambió respecto a la anterior). Luego el diagrama, con su leyenda de colores. Al final, en verde, 👉 la conclusión: lo que tienes que llevarte.

Demo 2.5 · Tools built-in: Grep, Glob, Read, Edit (Agent SDK)

¿De qué va esta demo? (clic para ocultar)

📖 De qué trata esta demo

Las tools built-in de Claude Code y cuándo usar cada una:

| Tool | Para qué | |---|---| | Grep | Buscar contenido dentro de archivos (quién llama a una función, un mensaje de error) | | Glob | Buscar archivos por patrón de nombre o ruta (**/*.test.ts); no mira el contenido | | Read | Leer un archivo | | Edit | Cambio puntual: reemplaza un texto que debe ser único; si no lo es, falla | | Write | Sobrescribir el archivo completo (respaldo cuando Edit no puede) |

🧪 Qué cambia entre una corrida y otra

  • Quita "Grep" de D25_TOOLS: tendrá que abrir archivo por archivo con Read (más turnos y tokens).
  • D25_EDIT_RESPALDO = "read_write" (con "Write" en D25_TOOLS): el Edit de solo 10000 falla por texto repetido y el agente usa Read + Write, que es lo que espera el examen.
  • Quita "Glob": encontrar los *.test.ts se vuelve más difícil.
  • Cambia D25_TAREA para pedir que cambie "el 10000" sin decir cuál y observa el error de Edit.

🎓 Lo que pregunta el examen

  • Grep para contenido, Glob para rutas, Edit para cambios puntuales con texto único, y Read + Write como respaldo.
  • Explorar de forma incremental: Grep para encontrar puntos de entrada y Read para seguir imports, en lugar de leer todo.
  • Rastrear una función a través de módulos que la re-exportan: identificar los nombres exportados y buscar cada uno.
