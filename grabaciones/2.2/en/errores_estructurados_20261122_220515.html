─────────────────  DEMO 2.2 · Structured errors: so Claude knows WHAT failed and WHAT to do  ─────────────────

╭───────────────────────────────────────────── 💡 Exam concept ──────────────────────────────────────────────╮
│                                                                                                            │
│  A generic error ('Operation failed') doesn't tell Claude whether to retry, ask for other data or          │
│  escalate. Worse: returning an empty list when the system failed makes Claude say something FALSE ('you    │
│  have no orders').                                                                                         │
│  Structured error = is_error: true + errorCategory (transient / validation / business / permission) +      │
│  isRetryable + a readable description. And a valid empty result is NOT an error.                           │
│  In MCP the field is called isError in the tool's result; in the Messages API it's is_error in the         │
│  tool_result block. Same idea.                                                                             │
│                                                                                                            │
╰────────────────────────────────────────────────────────────────────────────────────────────────────────────╯
╭──────────────────────────────────────────── The tool we'll use ────────────────────────────────────────────╮
│ {                                                                                                          │
│   "name": "buscar_pedidos_cliente",                                                                        │
│   "description": "Devuelve los pedidos de un cliente a partir de su email. Opcionalmente filtra por año.   │
│ Si la tool devuelve un error, lee errorCategory e isRetryable para decidir qué hacer.",                    │
│   "input_schema": {                                                                                        │
│     "type": "object",                                                                                      │
│     "properties": {                                                                                        │
│       "email": {                                                                                           │
│         "type": "string",                                                                                  │
│         "description": "Email del cliente"                                                                 │
│       },                                                                                                   │
│       "anio": {                                                                                            │
│         "type": "integer",                                                                                 │
│         "description": "Año a consultar (opcional)"                                                        │
│       }                                                                                                    │
│     },                                                                                                     │
│     "required": [                                                                                          │
│       "email"                                                                                              │
│     ]                                                                                                      │
│   }                                                                                                        │
│ }                                                                                                          │

👉 In «caido», the generic one returns an empty list with no error: Claude has no way of knowing the system failed. The structured one says what happened (errorCategory), whether retrying helps (isRetryable) and what to do (description).
